# Quiz platform: design

A static, multi-subject quiz app hosted on GitHub Pages. Quizzes are **not** in this repo: they are folders in any
public GitHub repo (or a local folder), each described by a `manifest.json`. The app has no backend; the quiz being
taken is identified entirely by the page URL.

Status: everything described here is implemented and tested: `src/core/` (loading, validation, grading, exam sampling,
sharing, storage, theming, rendering), the UI (`src/app`, `src/features`, `src/ui`), the CLI tools in `scripts/` and the demo
quiz. See §10 for how the UI is organized and the behaviours worth knowing.

`src/core` is written in *erasable* TypeScript (no enums or constructor parameter properties; enforced by
`erasableSyntaxOnly`), so Node 22.18+ can import it directly. That is how `scripts/validate.ts` and
`scripts/convert-legacy.ts` run the very same loader and validator as the app.

## 1. Architecture

All I/O sits behind `QuizSource`, so nothing else knows where a quiz came from.

```ts
interface QuizSource {
  readonly slug: string                    // storage namespace, see §6
  readonly label: string                   // human readable ("owner/repo@ref/path", "local folder: x")
  readText(path: string): Promise<string>  // path is manifest-relative, already normalized
  assetUrl(path: string): string           // raw.githubusercontent URL, blob: URL or same-origin URL
  urlFor(path: string): string             // the URL readText fetches (used in diagnostics)
  reload?(): Promise<QuizSource>           // local directory handles only
  dispose?(): void                         // revokes blob: URLs
}
```

Implementations: `GitHubSource`, `LocalFolderSource` (from `FileList`, or `FileSystemDirectoryHandle` with reload),
`BundledSource` (the demo).

```
src/core/                       framework-free, unit tested (vitest)
  model/types.ts                Manifest, Question union, Answer, Diagnostic
  random.ts                     mulberry32, seed derivation, shuffle
  text/                         normalize (code/prose), numeric (learner input), formula (author DSL)
  schema/                       schemas.ts (single source of truth) → public/schema/*.json, ajv validation,
                                diagnostics mapping
  question-types/               one file per type: grade() + check() (semantic validation); index.ts registry
  instance.ts                   one concrete showing of a question: seeds, shuffles, sampled options, numbers
  source/                       QuizSource, parse pasted URLs, slug, github, local, bundled, memory (tests/CLI)
  load/loadQuiz.ts              manifest → questions → reference/theme, all with diagnostics
  exam/                         weighted sampling, scoring with topic/type breakdown
  share/                        URL ⇄ source + exam preset
  storage/                      namespaced localStorage
  theme/                        theme.json → sanitized CSS custom properties
  content/                      Markdown + KaTeX + highlight.js + DOMPurify, relative asset rewriting
src/app                         App (address bar ⇄ state, loading, local reload), QuizShell (header, routes, drawers), QuizContext
src/features                    hub/, practice/, exam/ (builder, runner, results), reference/, question/ (one renderer per type)
src/ui                          Markdown, Drawer/ConfirmDialog, Toast, NumberField, dnd (click-or-drag chips), styles.css
public/schema/*.json            generated by `npm run schemas`; authors reference them with "$schema"
public/samples/demo/            bundled sample quiz (partly converted from the legacy repo)
scripts/validate.ts             `npm run validate -- <folder>`: the app's loader on a folder, diagnostics on stdout
scripts/convert-legacy.ts       neural-networks-pa-practice → new format
scripts/emit-schemas.ts         `npm run schemas`: schemas.ts → public/schema/*.json (a test fails if they drift)
```

Deviation from the first proposal: grading and semantic validation live in `core/question-types/` (pure), and the React
renderers live in `features/question/` and are looked up by `type`. Adding a type = a schema entry, a `question-types/` file,
a renderer.

Libraries: `ajv` (validation), `marked` + `katex` + `highlight.js` (`lib/common`, not lazy) + `DOMPurify` (rendering),
`@dnd-kit` (drag mechanics, added with the UI), React 19, Vite.

Security: everything rendered from a quiz passes through DOMPurify. KaTeX output is generated after sanitizing, from a
placeholder, so it cannot be forged by the author's HTML. `theme.json` values are validated per token, never injected as raw
CSS. Links get `rel="noopener noreferrer"`.

## 2. Folder contract

```
<any folder in a public repo>/
  manifest.json          required
  questions/*.json|jsonl listed in the manifest
  reference.md|json      optional
  theme.json             optional
  assets/…               anything referenced by relative path
```

Raw URLs cannot list a directory, so **the manifest lists every question file**. All relative paths (manifest fields,
Markdown images and links) resolve against the manifest's folder. Absolute URLs pass through; `../` that would leave the
folder is rejected (diagnostic, asset not rewritten).

`raw.githubusercontent.com` sends `access-control-allow-origin: *` (also on 404s, so "not found" is distinguishable from a
network failure) and caches for 300 s: a push can take up to 5 minutes to show. Use a commit SHA as `ref` for an immutable
link, or a local folder while authoring. Refs containing `/` are tried as `<ref>`, then `refs/heads/<ref>`, then
`refs/tags/<ref>`.

### manifest.json

```jsonc
{
  "$schema": "https://<pages-host>/schema/manifest.schema.json",
  "schemaVersion": 1,
  "title": "Algorithms Midterm Prep",              // required
  "description": "Chapters 1–6",                    // required, Markdown
  "author": "…", "version": "…",                    // optional
  "topics": [ { "id": "sorting", "title": "Sorting" }, "graphs" ],   // required; string = id and title
  "questions": ["questions/sorting.json", "questions/graphs.jsonl"], // required, .json (array) or .jsonl
  "reference": "reference.md",                      // optional (.md or .json)
  "theme": "theme.json",                            // optional: path or inline object
  "exam": { "count": 20, "minutes": 45 }            // optional defaults for the exam builder
}
```

### theme.json

```jsonc
{ "scheme": "dark", "accent": "#7c5cff", "accentSecondary": "#22d3ee",
  "bgPrimary": "#0b0d12", "bgSurface": "#141824",
  "fontSans": "Inter, system-ui, sans-serif", "fontMono": "JetBrains Mono, monospace", "radius": "10px" }
```

Maps to `--accent --accent-secondary --bg-primary --bg-surface --font-sans --font-mono --radius` (+ derived `--on-accent`,
`color-scheme`). Colors: hex, `rgb()`, `hsl()`, `oklch()`. Fonts: family lists only (no `url()`, braces or semicolons), no
web-font loading. Radius: `px`/`rem`/`em`. An invalid token is dropped with a warning; the rest still applies. Text, border and
muted colors derive from `scheme`; a contrast warning is emitted when accent-on-surface or text-on-background can be computed
and is below 4.5:1.

### reference.json

`{ "entries": [ { name, aliases?, kind?, module?, signature?, summary, parameters?: [{name, type?, default?, description}],
returns?, example?, notes?, see_also?, tags? } ] }`. `reference.md` is rendered as Markdown with a table of contents and
search. Questions link to entries with `reference: ["name", …]`.

## 3. Questions

Authoritative field list: `src/core/schema/schemas.ts` (emitted to `public/schema/question.schema.json`). Unknown fields are
errors, with a "did you mean" suggestion, so typos such as `explaination` are not silently ignored.

Common fields: `id` (unique, stable; progress is keyed by it), `type`, `topic` (a declared topic id), `prompt` (Markdown,
`$math$`, optional for `fill-blank`), `title?`, `difficulty?` (`easy|medium|hard`), `tags?`, `hints?`, `explanation?`
(Markdown), `points?` (default 1), `reference?`.

| type | fields | grading (score 0..1) |
|---|---|---|
| `fill-blank` | `template` (text with `<<BLANK:id>>`), `language?` (if set the template is a code block and matching is code-aware; otherwise Markdown prose, matched case-insensitively), `mode?` (`text` default, `choice`, `drag`), `blanks[{id, answers[], patterns?[], label?, placeholder?, multiline?, caseSensitive?, mode?(text/choice override), options?[] or distractors?[]+show? (choice)}]`, `distractors?[]` (drag bank) | fraction of correct blanks |
| `code-debug` | `language?`, `code`, `errors[{line, fixes[], options?[], explanation?}]` (1-based lines). Learner flags lines, then types a fix (or picks one when `options` is given) | (correct flags with right fix − false flags) / errors, floored at 0 |
| `mcq` | `options[{text, correct, explanation?}]` (exactly one correct), `shuffle?` | 0 or 1 |
| `multi-select` | same options (≥1 correct), `grading?` (`all-or-nothing` default, `partial`), `shuffle?` | partial: max(0, (right − wrong) / total correct) |
| `calculation` | `code?`, `parts[{id, label?, value \| formula, tolerance?, unit?}]`, `variables?`, `constraints?`. See below | fraction of correct parts |
| `ordering` | `items[]` in correct order (shuffled on display), `language?` (code/Parsons lines), `grading?` (`exact` default, `partial`) | partial: fraction of item pairs in the right relative order |
| `matching` | `pairs[{left, right}]` (rights may repeat), `distractors?[]`, `grading?` (`partial` default, `all-or-nothing`) | fraction of correct pairs |
| `categorize` | `categories[{id, title, items[]}]` (≥2), `distractors?[]`, `distractorPenalty?` (0..1, default 0) | max(0, (correct placements − penalty × distractors placed) / items) |
| `short-answer` | `modelAnswer`, `rubric[{text, points?}]` | self-assessed: ticked points / total points |

`tolerance` is a number (absolute) or `{abs?, rel?}`; an answer passes if it is within `abs` **or** within `rel` (e.g.
`{"rel": 0.02}` = ±2%). No tolerance means exact (up to float noise). Learners may type expressions (`432*6+6`, `2,598`).

### Randomized calculations

`calculation` with no `variables` is a static question; with `variables` it is the old `generated_calc`:

```jsonc
{ "variables": { "H": {"choices": [28, 32]}, "k": {"min": 3, "max": 7, "step": 2}, "out": {"formula": "H - k + 1"} },
  "constraints": ["out > 0"],
  "prompt": "Input height {{H}}, kernel {{k}}. Output height?",
  "parts": [ { "id": "h", "formula": "H - k + 1" } ] }
```

Variables are drawn in declaration order, re-drawn until all constraints are non-zero. `{{expr}}` / `{{expr:2}}` is replaced
in `prompt`, `code`, `hints`, `explanation` and part `label`/`unit`. The formula language is the reference repo's
(`+ - * / % ^ **`, comparisons, `&& || !`, `floor ceil round trunc abs sign sqrt exp ln log log2 log10 pow min max`,
`pi e`). Loading checks 50 draws of each template, so a broken template becomes a diagnostic, not a runtime error.

### Instances and seeds

Everything random about a showing (variable values, shuffled options/items/chips, sampled distractors) is a pure function of
`(question, seed)` in `core/instance.ts`.

* **Practice:** the seed is random per showing; "New numbers" re-rolls it.
* **Exam:** `seed = deriveSeed(examSeed, questionId)`, so a shared exam link yields identical numbers *and* identical shuffles.

### Interaction contract for drag types (`fill-blank` drag, `categorize`; `ordering` for lists)

Every drag mechanic must also work without dragging: click a chip to select it, then click a blank/bucket to place it
(click a placed chip to return it); keyboard: Tab to a chip, Enter/Space to pick it up, Tab to a target, Enter to place;
ordering additionally has up/down buttons. `matching` uses a per-row selector (rights are reusable).

## 4. Validation and diagnostics

Two layers: ajv against the JSON Schema (discriminated on `type`), then per-type semantic `check()`s (unique ids, topic
declared, blank markers ⇄ `blanks`, line numbers inside `code`, exactly one correct option, regexes compile, `answers` ⊆
`options` for static choice, calculation templates evaluate over 50 draws, referenced images exist in the folder, …).

```ts
interface Diagnostic { severity: 'error'|'warning'; file?: string; line?: number /* JSONL */; index?: number;
                       id?: string; path?: string /* JSON pointer */; message: string; hint?: string }
```

* Manifest problems, or a missing `manifest.json`, are fatal (the message names the exact URL tried and the usual causes).
* A question with errors is **skipped**, the rest of the quiz stays usable, and the UI shows a banner ("3 questions skipped")
  listing each diagnostic. A bad JSONL line only skips that line.
* Warnings (theme contrast, missing optional asset, duplicate tags) never skip anything.

## 5. URLs

```
?repo=owner/name&path=course-1/midterm&ref=main     ref defaults to main, path to the repo root
?…&preset=<base64url(JSON)>                          optional exam preset
?sample=demo                                         bundled sample
#/practice/<questionId>   #/exam                     in-app view (hash, so no reload and no 404.html hack)
```

Local folders have no shareable URL (the Copy Share Link button is disabled with an explanation).

Preset JSON (compact keys, versioned): `{"v":1,"n":20,"m":45,"tp":["sorting"],"ty":["mcq"],"d":["hard"],
"w":{"sorting":60,"graphs":40},"seed":12345,"sh":1}` = count, minutes, topic filter, type filter, difficulty filter, topic
weights (%), seed, shuffle order. Decoding is defensive: size cap, version check, shape check, clamping.

The hub's paste box accepts `https://github.com/o/r/tree/<ref>/<path>` (ref = first segment, editable), `…/blob/…/manifest.json`,
`raw.githubusercontent.com/…` URLs, and `owner/repo[/path]`.

## 6. Persistence

Slug: `gh:{owner}/{repo}@{ref}#{path}` (owner and repo lowercased, path trimmed of slashes); local folders: `local:{folderName}`.

```
quiz:v1:_recent            [{slug, source, title, openedAt}]  (max 20)
quiz:v1:{slug}:attempts    {qid: {score, best, attempts, at, seed}}
quiz:v1:{slug}:flags       [qid]
quiz:v1:{slug}:exams       [ExamResult]  (max 50)
quiz:v1:{slug}:ui          filters / last position
```

Different refs are separate progress on purpose. Entries for removed question ids are ignored. Status filters: *Unanswered*
(no attempt), *Incorrect* (last score < 1), *Flagged*.

## 7. Exams

Weights are percentages per topic. Topics without a weight share the remainder equally (`100 − Σ set`); if every topic has a
weight, or the remainder is ≤ 0, weights are normalized. With **no** weights at all every question is equally likely
(a topic's share is proportional to its size). Allocation: largest-remainder rounding, capped by the number of
questions available per topic after type/difficulty filters; any shortfall is redistributed over topics that still have
capacity. A warning is returned when the pool is smaller than the requested count. Selection within a topic and the final
order use the seeded RNG. Results: total, score by topic and by type (points-weighted), `short-answer` questions count once
self-graded.

## 8. Local preview

`Load local folder` uses `showDirectoryPicker` where available (Chromium): the directory is re-scanned on a Reload button
and on window focus, so edits show up without re-picking. Elsewhere `<input webkitdirectory>` gives a one-shot snapshot.
Images become `blob:` URLs. If `manifest.json` is not at the picked folder's root but exactly one level down, the diagnostic
says so.

## 9. Legacy migration

`npm run convert-legacy -- <legacy-repo> <out-dir> [--only a,b]` (also validates its own output) maps `fill_blank→fill-blank`, `find_fix→code-debug`,
`code_choice→fill-blank (mode choice, distractors+show)`, `multiple_choice→mcq|multi-select`,
`calculation|param_count→calculation`, `generated_calc→calculation (variables)`, `open_ended→short-answer`;
`category→topic`; `related_reference→reference`; `source` and `slides` are dropped (reported). The PyTorch reference is copied.

## 10. The UI

**Routing.** The query string selects the quiz (§5) and is the only thing the app reopens on `popstate`; the hash selects the
view (`#/practice/<id>`, `#/exam`, `#/exam/run`, `#/exam/result`). Browsers fire `popstate` for hash-only changes, so the app
compares the query string with the one it last acted on and ignores those events (otherwise every Next would reload the quiz).

**Practice.** One question at a time with Check / Try again / Hint (one at a time) / Flag, plus "New numbers" (randomized
calculations) or "New options" (sampled choice blanks). The Browse drawer (`/` or Ctrl/⌘ K) searches title, id, tags, topic and
prompt and filters by status, topic, type and difficulty; the same filtered list is what Prev/Next/`n` walk through, and the
filters are remembered per quiz. Shortcuts: `j`/`k`/arrows, `n`, `f`, `h`, `1–9`, Ctrl/⌘ Enter, `r`, `?`.

**Exam.** The builder shows the allocation the current weights produce (and warnings) before you start. A running exam has a
navigator grid (answered / flagged / current), no feedback, no hints, and a countdown that auto-submits at zero. Results show
the score by topic and type and a review list; short answers are self-graded there and the saved history entry is updated.
Answered exam questions are also recorded as practice attempts. Answers are kept in memory only (a running exam is lost on
reload; the browser asks before leaving).

**Drag mechanics.** `fill-blank` drag mode and `categorize` use one model (`ui/dnd.tsx`): drag a chip onto a target, or select it
(click / Enter) and then activate a target (click / Enter). `ordering` uses `@dnd-kit/sortable` with a keyboard sensor plus ↑/↓
buttons. `matching` uses one `<select>` per row, so right-hand values are reusable.

**code-debug options.** Offering a dropdown only on the real bug lines would reveal them, so options are used only when *every*
error has them; then every flagged line gets the same pooled, shuffled list (a semantic warning flags the mixed case).

**Local folders.** With `showDirectoryPicker` the folder is re-read from the Reload button and whenever the window regains focus;
a focus reload that finds nothing changed keeps the current state (a half-typed answer survives), and a broken file shows the
diagnostics and recovers when fixed. `webkitdirectory` is a one-shot snapshot.

**Performance.** The start page is ~80 kB gzipped; the quiz screen, validator, KaTeX and highlight.js load when a quiz opens.

**Not done.** Resuming a running exam after a reload; per-question answer history; question-level time tracking.
